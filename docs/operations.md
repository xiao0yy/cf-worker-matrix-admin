# 管理端日常操作

管理端通过 Cloudflare Access 授权并向 R2 提交固定命令，VPS 的同一 Go 程序
执行。网页关闭不影响执行，不需要 SSH。各实例首先升级到支持
`management_protocol: 1` 的版本；旧版本会显示升级提示，不显示虚假的成功。

## 备用实例与升级

新 VPS 按同版本 AGENT.md 准备依赖、填写 R2 s3.env、执行 prepare。它只注册
standby 和轮询，不会复制数据库、备份、接管或自动安装更新。公网 IPv4 会自动
探测；识别到多个公网地址时不猜测，人工登记的地址优先。出口地址不证明入站可达。

在「运维工具 → 版本与配置」检查公开版本，选择固定版本后安装。UI 展示的版本
必须有可验证的 manifest.json；版本发现有一小时缓存，不自动升级。旧版缺少远程
维护能力时，由 Agent 下载完整新包完成一次升级，之后可从 UI 管理 standby。
正在服务的实例先停用，再安装；安装结束仍停用，由你显式恢复。

升级失败保留 pending-update 和旧程序目录。重试同一个任务与版本；下载失败可以
取消，进入安装阶段后等待收尾，避免中止 systemd 配置更新。若连管理进程也无法
运行，Agent 用相同新包执行 upgrade --apply，不重新 prepare 或重造实例身份。

## 常规切换

1. 目标实例运行「接管预检」，检查依赖、R2 配置、B2 仓库身份、快照可读性、
   磁盘空间及固定镜像。预检通过仅表示准备就绪，未启动业务。
2. 将 Cloudflare 回源改到目标；可使用已配置的 DNS 管理功能或手动修改。
3. 在「切换实例」选目标并确认。预检须在最近 10 分钟内通过，且对应当前 epoch。
4. 旧实例关闭入口、停止所有写者、完成最终备份并释放；目标恢复、隔离验证后上线。
5. 从 Telegram 和 Matrix 各发一条新消息。可在「版本与配置」记录双向验证结果。
6. 需要腾出旧机空间时，再在旧实例生成清理计划、审阅具体路径并确认执行。

暂停只停止下一步推进，保留已经停用、已备份或已变更的归属。可以继续原任务；
STARTING 后不会重新恢复覆盖可能新增的消息。若要回旧机且归属已释放，需要新的
正常切换，不能把旧 epoch 恢复为 owner。

## 旧机故障：从备份强制接管

1. **在 VPS 平台确认旧写者已关机或完全隔离**。HTTP 不通、心跳消失、改 DNS
   均不足以证明旧机停写，Telegram 仍可能在后台连接。原切换中断时，也要隔离
   之前的目标实例。管理端列出必须确认的节点。
2. 启动另一台 standby，将 Cloudflare 回源改到它。
3. 点击「运维工具 → 强制接管」，选择目标、恢复点，填写隔离方式及记录。
   确认所选时间之后的数据可能丢失，输入“强制接管”后提交。
4. 目标先预检，再以 CAS 取得下一 epoch，恢复所选数据、隔离验证并上线。
   没有旧机最终备份，不会伪造停机证明。在线快照的两个数据库采样时刻可能不同。
5. 若失败，查看任务和切换记录。未开始写入时可重试同一任务；开始写入后修复
   当前 generation。若改选第三台，须再次隔离所有可能写入的旧节点。

程序无法替你验证云主机已经断电，隔离声明的真实性由操作者保证。不会根据心跳
自动接管。旧机恢复连接后看到更高 epoch，会保持停用，不能自行恢复旧数据上线。

## 备份、任务与空间

- 「备份与恢复」：立即备份、完整回读校验、恢复点历史和隔离恢复演练。
  媒体继续使用 Tuwunel 的 S3，不重复备份。演练不修改生产挂载或启动业务。
- 「任务记录」：任务阶段、结果、错误，以及定时备份状态。APPLIED 表示命令已
  接收；任务 SUCCEEDED 才表示执行完成。取消不撤销已发生的副作用。
  INTERRUPTED 不自动重放，检查后显式重试。原 authority 已变化时重新提交任务。
- 「空间回收」：先设置保留数量/天数，生成并审阅计划，再确认执行。latest、
  当前及已完成切换恢复点、活跃恢复任务选中的点会被保护。不会删除未知孤儿快照、
  R2 配置或 S3 媒体。计划本地保存，执行核验原始哈希和 epoch。
- 远端回收须先停用当前 owner，进入 MAINTENANCE 后执行固定快照的 forget、
  prune 和 check。中断保留维护态，可重试同任务；计划过期或不继续删除时，
  「校验并结束存储维护」通过 check 后退出，业务仍需显式恢复。
- 本地清理计划只允许已停用、非 owner 的实例，且替代实例有新鲜的 ONLINE 报告。
  只删除计划内的旧数据库和 recovery generation，保留身份、配置及远端数据。
  远端计划有效期 24 小时，本地计划 1 小时，过期重新生成。

容器运行和 HTTP 健康不等于 Telegram 投递正常。人工双向验证记录只保留 15 分钟
有效性，不代替新的实际消息验证。诊断导出可能包含机器信息和错误，分享前脱敏。
